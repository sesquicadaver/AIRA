# Читати результат

## Що це?

Спочатку **відповідь**, далі статус виконання, перевірка й **походження**. Технічні хеші та сирий JSON — у «Деталях», не як перше, що треба розшифрувати.

## Що зробити?

1. Прочитайте текст відповіді.
2. Прочитайте **Походження**: mock ≠ перевірено; невизначена чи неактивна модель зазначена; локальна генерація не стає VERIFIED автоматично.
3. Прочитайте **Запитано / Застосовано / Виконано**: що Work просив, що було вибрано/допущено на submit, і що реально виконалось. Для reference mock Виконано = `mock (модель не запускалась)` — не requested model_ref.
4. Відкривайте **Деталі** лише для технічного JSON.

## Що має відбутися?

Чесний рядок provenance і трійка моделі для цього запуску. Вбудовані обчислення можуть показати VERIFIED, коли шлях виконання справді перевірив результат; вільна генерація без того шляху не підробляє VERIFIED. На Роботі видно помітний демо-банер, поки staff executor лишається reference mock.

## Що робити, якщо не вдалося?

- Відповіді ще немає → очікування (help:work.waiting) або події.
- Стани collapse / needs-human можуть не мати фейкової відповіді — йдіть за повідомленням.
- Генерація впала через відсутність моделі → help:model.unavailable.
- Демо/mock банер → Параметри → Моделі (або process backend); вибір ≠ VERIFIED.

## Пов'язані теми

- help:work.submit — ще один запуск
- help:model.unavailable — коли модель потрібна, але відсутня
- help:model.select — каталог у Параметрах
- help:start — шлях першого запуску
