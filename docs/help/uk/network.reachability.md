# Доступність

## Що це?

Доступність — **останнє спостереження** mesh: пряма, relay, лише outbound, лише локально, невідомо або offline, коли це справді спостерігали. Застаріле чи unknown не малюється як підтверджене глобальне з’єднання.

## Що зробити?

1. **Стан системи → З’єднання**.
2. Спочатку пройдіть сценарій з’єднання, якщо ще немає запрошення або лишилися на P0 — help:network.connect (invite → P1/P2 → Стоп/Старт).
3. **Оновити** (або наступний крок на З’єднанні, якщо він саме про оновлення) — новий запит спостереження.
4. Читайте людський підсумок і час спостереження — не лише кількість адресної книги. Сирі enum — у технічних подробицях.

## Що має відбутися?

Чесний висновок. Рядки AddressBook не рахуються як живі сесії. UNKNOWN ≠ OFFLINE. Мова мережі в рядку стану узгоджена зі З’єднанням. Завершення кроків **налаштування** з’єднання не вигадує віддалену сесію; loopback listen — не dial-адреса peer (help:network.connect).

## Що робити, якщо не вдалося?

- UNKNOWN після peer-профілю → peer listen, firewall, help:network.connect / help:node.lifecycle.
- Програма зупинена → help:node.lifecycle.
- Щойно змінили профіль → help:settings.apply (потрібен перезапуск).
- Порожня книга / немає довіри → help:network.trust.

## Пов'язані теми

- help:network.connect — сценарій invite → профіль → перезапуск (**налаштування**; setup ≠ remote; loopback ≠ dial)
- help:network.trust — довіра vs discovery
- help:node.lifecycle — Старт / Стоп / Оновити
