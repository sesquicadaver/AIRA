# Вибір моделі

## Що це?

Локальні моделі належать до model / execution layer — **не** `aira-core`, не GPU-маркетплейс і не вигадуються екраном Роботи. Довідка працює **офлайн** (вбудовані статті; без мережі й без LLM для читання цієї теми).

**Параметри ≠ Стан системи:** каталог змінюйте лише в **Параметри → Моделі**. **Стан системи → Модель** показує **selected**, **ready** і **used** як спостережувані факти — це не другий редактор каталогу. Є один каталог і два джерела: **Хостовий Ollama** і **Локальний файл**. Кожне джерело показує лише свої дії.

Придатність рядка хоста — один із п’яти спільних станів: **Готова**, **Підготувати й виконати**, **Перевіряємо…**, **Потрібна дія** або **Несумісна**. Суфікс імені на кшталт `:cloud` — лише підказка; він **не** доводить, що модель виконується на цьому комп’ютері. Місце береться з полів API підтримуваної версії Ollama, а не з підпису.

## Що зробити?

Канонічний шлях Desktop (CLI не обов’язковий):

1. Відкрийте **Параметри → Моделі** і оберіть **джерело**.
2. **Хостовий Ollama:** оновіть список, оберіть модель (вибір не змінює типову), потім **Зробити типовою** або **Використовувати Ollama process**. «Зробити типовою» записує типову модель (підписаний bind-маркер; не weight VERIFIED) і process для **наступного** старту вузла. Поки не **Зупинити** і знову **Запустити**, виконавець може лишатися mock. Якщо список ще завантажується, Use Ollama завершує прив’язку після відповіді списку.
3. **Локальний файл:** подивіться **Зберігання моделей** (лише observe). **Скан** або **Дозволити локальне додавання** → **Додати файл…**. **Шлях artifact** для **Перевірити** стоїть на цьому кроці додавання, не в технічних подробицях. **Вибрати** рядок (не VERIFIED). **Підготувати**, якщо це локальний файл і він ще не готовий. Рядки хостового Ollama тут не показуються і не мають Підготувати.
4. У **Роботі** селектор показує **Типова: назва**, з пошуком і фільтром **Сумісні** (**Показати всі** лишає несумісні з причиною). **Порівняти** відкриває другий селектор, не другий каталог. Якщо хостова модель зі списку придатна, але ще без слота — **Підготувати й виконати**: слот, допуск і один запуск; типову tip не змінює. Потрібна локальна модель. Якщо B падає — результат A лишається.
5. Якщо Робота заблокована через відсутність host LLM — прив’яжіть Ollama в Параметри → Моделі і перезапустіть. Mock не є продуктовим Work.

Опційний інструмент (не обов’язок GUI-шляху): `aira models scan|list|activate`; для Dev також env `AIRA_LLM_BACKEND=process`.

## Що має відбутися?

- Відсутність моделі **блокує** Роботу. Немає шляху, який завершується без локальної моделі.
- Desktop тримає **selected ≠ ready ≠ used** чесно — без вигаданого імені й без копіювання selected у used.
- Вибір / Підготувати / Select / **Підготувати й виконати** ніколи тихо не означають VERIFIED для вільного тексту.
- Порівняти ніколи тихо не підміняє неготову модель tip або іншим рядком каталогу.
- Хмара або невідоме місце лишаються в каталозі як **Потрібна дія** / **Перевіряємо…** і не стають локально готовими лише через суфікс `:cloud`.

## Що робити, якщо не вдалося?

- Генерація заблокована, бо нічого не ready → help:model.unavailable (ті самі кроки Параметри → Моделі).
- Порівняти заблоковано, бо A/B порожні, однакові або не ready → виправте ногу в Параметри → Моделі; не очікуйте, що Auto tip заповнить прогалину.
- Порожнє поле або «модель не вибрано» ≠ успішний локальний LLM.
- Якщо вузол Running — це Capability моделі, а не «AIRA зупинена» (help:node.lifecycle лише якщо не вдався Запустити вузол).

## Пов'язані теми

- help:model.unavailable — потрібна модель не готова
- help:settings.apply — де параметри збережені vs застосовані
- help:work.submit — запуск без вигаданої моделі
- help:work.result — банер mock і requested / applied / executed
