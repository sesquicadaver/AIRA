# Модель недоступна

## Що це?

Задача потребувала локальної генерації тексту, але підходяща модель не **ready** або не **selected** для generate. Це fail-closed сигнал — не тихий fallback на вигадану модель і не те саме, що «AIRA зупинена».

Довідка з цієї теми **офлайн** (вбудована; без мережі / без LLM для читання).

## Що зробити?

1. Якщо задача дозволяє — вбудовані обчислення (math не потребує моделі; Порівняти також не працює лише на math).
2. Відкрийте **Параметри → Моделі** (не Стан системи → Модель — там лише observe):
   - **Скан** каталогу або **Дозволити локальне додавання** → **Додати файл…**
   - **Вибрати** Auto або конкретний доступний рядок
   - **Підготувати**, доки ready; читайте reason готовності
3. У **Роботі** встановіть виконавець **Авто**, **Конкретна модель** або **Порівняти** (дві різні ready моделі) і знову **Виконати**.
4. Якщо Порівняти заблоковано — виправте неготову ногу (A або B); UI не підставить tip замість неї.
5. Якщо змінювали лише параметри, що потребують apply/restart — help:settings.apply / help:node.lifecycle.

Опційний CLI (`aira models …`) **не** обов’язковий, коли доступні кнопки каталогу в Параметрах.

## Що має відбутися?

Детерміноване виконання може успішно завершитися без LLM. Generate лишається недоступним, доки немає реального підготовленого/вибраного backend. Після успішного шляху selected ≠ ready ≠ used лишається чесним. Порівняти ніколи тихо не підміняє неготову модель.

## Що робити, якщо не вдалося?

- Не очікуйте VERIFIED для вільного тексту без ready backend.
- Demo / reference mock на Роботі ≠ «модель доступна» для реальної генерації — help:work.result і Параметри → Моделі.
- Якщо **Виконати** не може Запустити вузол — спочатку help:node.lifecycle.

## Пов'язані теми

- help:model.select — вибір / підготовка локальної моделі в Параметрах
- help:work.submit — повторити задачу
- help:work.result — provenance після генерації (або mock)
- help:node.lifecycle — коли сам вузол не стартує
