# З’єднання з учасниками

## Що це?

**З’єднання** — як цей комп’ютер долучається до інших учасників AIRA. Типовий профіль **P0** — лише локально. Рядки адресної книги — збережені учасники, не живі сесії. UNKNOWN — це не те саме, що OFFLINE.

Ця тема — коли потрібен робочий шлях до іншої людини: запрошення → профіль із peer → Стоп/Старт → чесний стан.

## Що зробити?

Канонічний сценарій (базовий шлях без обов’язкового розгортання «Технічні подробиці»):

1. **Імпортуйте запрошення** — у **Стан системи → З’єднання** скористайтесь **Імпортувати запрошення…** / імпорт JSON або QR (friend invite). Це довіра до відомого peer; саме discovery ще не довіра (див. help:network.trust).
2. **Увімкніть peer-профіль** — оберіть **P1** або **P2** (приватна мережа з peer listen). P0 лишається лише локальним. Якщо кнопка каже **Увімкнути приватну мережу** — натисніть її.
3. **Застосуйте Стоп → Старт** — якщо Параметри або З’єднання показують **потрібен перезапуск**, у **Стан системи → Програма** натисніть **Стоп**, потім **Старт**. Закриття вікна не зупиняє AIRA.
4. **Перевірте стан** — читайте людський підсумок З’єднання і за потреби **Оновити**. Деталі спостережуваної доступності — help:network.reachability.

Не вмикайте public bind і не auto-trust незнайомців за порадою з Довідки — це лишається opt-in CLI / advanced у технічних подробицях.

## Що має відбутися?

Після invite + P1/P2 + перезапуску: Збережено ≠ Застосовано, доки runtime не підтвердить; «потрібен перезапуск» зникає після Стоп/Старт; книга може зрости без вигаданих живих сесій; на З’єднанні видно один наступний крок (CTA), якщо чогось ще бракує.

## Що робити, якщо не вдалося?

- Немає запрошення / порожня книга → імпорт ще раз (help:network.trust).
- Досі P0 / «Увімкнути приватну мережу» → P1 або P2, потім перезапуск.
- «Потрібен перезапуск» лишається → Стоп, потім Старт (help:settings.apply, help:node.lifecycle).
- Банер лишається unknown після peer-профілю → Оновити й help:network.reachability (UNKNOWN ≠ OFFLINE).
