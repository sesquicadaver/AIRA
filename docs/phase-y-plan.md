## Правила, зафіксовані до реалізації

- Придатна B без слота не блокується назавжди. Дія — **«Підготувати й виконати»**: ідемпотентний атомарний слот, потім чинний допуск, потім запуск. Окремої ручної підготовки немає. «Зробити типовою» — єдина зміна `activated.latest`.
- Один явний endpoint для списку і для `ollama run` уже в `#366`, до метаданих.
- `/api/show` викликається, коли бракує будь-якого поля оцінки, не лише capabilities.
- «На сервері, не в його хмарі» підтверджують `remote_host` і `remote_model` лише тієї версії API, чий контракт вважає порожнечу локальним виконанням на сервері. Невідома версія: порожнє поле — це «невідомо». `localhost` і суфікс `:cloud` самі по собі нічого не вирішують. «На цьому комп’ютері» — лише якщо модель локальна щодо сервера і сервер є цією машиною.
- Готова будь-яка модель з capability `completion`, яка виконує решту умов, включно з `completion` разом із `vision` або `embedding`. Сам `embedding` без `completion` несумісний. `vision` не вмикає ввід зображень.
- Для `kimi-k2.7-code:cloud` місце береться з полів API. Поки воно невідоме або віддалене, рядок лишається в каталозі і не готовий як локальний.
