# Правила аналітичного шару Analyze-N

## 1. Immutability первісних документів

1. Не редагувати файли в `Manifesto etc/` і `Meditation_About/`.
2. Не робити «тихі» rename/move originals у `specs/` без окремого явного рішення власника (і навіть тоді — краще copy, не mutate).
3. Цитати з originals — з шляхом і секцією; не переписувати original «краще».

## 2. Evidence vs Inference

Кожне матеріальне твердження в Analyze-*:

- **Evidence** — пряма цитата / посилання на файл первісного корпусу
- **Inference** — висновок аналітика (явно мітити)
- **Unknown** — немає доказу в корпусі

## 3. Куди писати що

| Тип | Куди |
|-----|------|
| Спостереження / розбір книги | `book-analyses/` |
| Матриці відповідності | `matrices/` |
| Карта корпусу / статуси | `provenance/` |
| Дефекти, stubs, суперечності | `todo/TODO_FIXME.md` |
| Living Spec | `LIVING_SPEC_MATRIX.md` |
| Перевірки циклу | `verification/` |

## 4. Anti-stub для аналітики

Заборонено в Analyze-*:

- порожні заглушки «TODO пізніше» без опису проблеми;
- твердження без джерела, видані за факт;
- «виправлення» первісного ТЗ під виглядом аналізу.

Дозволено:

- `TODO_FIXME` з severity і посиланням на evidence;
- пропозиції RFC як **чернетки в Analyze-***, не як правки Book *.

## 5. Версіонування циклів

Новий великий прохід аналізу → нова тека `Analyze-2`, `Analyze-3`, …  
Не змішувати несумісні хвилі в одній теці без INDEX-посилань.
